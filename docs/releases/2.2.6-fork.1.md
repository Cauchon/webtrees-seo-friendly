# webtrees-seo-friendly 2.2.6-fork.1

**Status: planned; unpublished.** These notes describe the proposed first fork
release. Do not publish the tag or release, or deploy the artifact, until the
owner completes the migration gate, validates the final distribution, and
approves publication. A local preparation tag may be used to build and test the
candidate ZIP.

## What changes

This release is based on the published webtrees 2.2.6 stable source. It keeps
upstream's bot block list intact and applies a separate fork policy for
public-reading services. Selected search crawlers, link previews, readers,
citation and archival tools, diagnostics, and user-requested fetches can reach
public content. Named model-training and bulk-collection agents remain blocked.
Private data still depends on webtrees authentication and tree privacy rules.

The middleware and generated `robots.txt` share the effective bot policy.
The robots template covers clean and query-routed URLs and includes a
robots-only `Applebot-Extended` opt-out. First-visit browser responses retain
application cookies while setting the test cookie. Robot requests to the bare
homepage use a redirect; unknown routes continue to return 404.

A new stable-sync workflow checks published upstream stable releases and
prepares draft PRs for owner review. It does not merge, tag, publish, or deploy.

## Installation and upgrade

The release artifact, when published, must be the attached
`webtrees-seo-friendly-2.2.6-fork.1.zip` distribution in
[Cauchon/webtrees-seo-friendly Releases](https://github.com/Cauchon/webtrees-seo-friendly/releases).
It is not available while this note remains planned. Use
[the installation guide](../installation.md) for requirements, backup, manual
upgrade, and robots verification. PHP 8.3 through 8.6 and the required
extensions and database driver are needed.

**Do not use the in-app automatic upgrade wizard.** It downloads upstream
webtrees and can replace this fork's policy. GitHub's generated source ZIP
also lacks the distribution's bundled PHP dependencies.

## Publication checks

Before publication, the owner must confirm the release commit and fork tag,
review the policy changes, complete PHP and robots-output validation, build
and inspect the distribution ZIP, record its SHA-256 digest, and test the
migration with a restorable backup. Record the final digest and validation
results in the published release notes. A merge or draft PR does not itself
make this release available or update any installation.
